# GPUI bump to zed@c016f436 (2026-11-25)

The pin moves from `703b5ac3` to `c016f436` on `main`
(`tasks/prd-gpui-c016f436-upgrade.md`). The commit before the bump is
`a3f53dbb` (GPUI `703b5ac3`, Rust 1.100.0); the bump is `8adf4abd` to
`7d1e4f6c` (US-001 to US-004), and every new-pin figure below comes from
`226032bf`, whose code is that of `7d1e4f6c` (the two commits after it touch
only `tasks/` and `.gitignore`). This file gathers what EP-002 measured on
Linux: the suites (US-005), keystroke latency and the unfocused frame cap
(US-006), the visual pass (US-007) and the Linux CI jobs (US-008).

Machine and session, for every section: Arthur's Fedora 45 machine, AMD Ryzen 7
7800X3D, NVIDIA GeForce RTX 4070 Ti SUPER on the 620.70.06 driver (open kernel
modules), GNOME Shell 51.1 on Wayland, Xwayland 24.1.15, two 2560 by 1440
displays at scale 1, kernel 7.3.4. Each commit was built in its own worktree
with its own target directory under `~/.cache/claude-c016-bench/` (outside the
repository; the captures and logs cited below stay there and are local
evidence that no other agent can read).

## Linux suites (US-005)

Release profile. Runs interleaved: in each round the old pin, the new pin and
the new pin again ("same binary again", the noise of the run itself), the
order reversed every other round, every process pinned to CPU 2 with
`taskset` (startup: CPUs 2 to 7). Before each run the driver waited for a
one-minute load under 1.2 and no build or leftover bench process (loads read
0.53 to 1.19; the longest wait was 180 s), and the other agent session on the
machine held its builds for the whole set. Each value is the median of the
per-run medians. CPU share: 0.99 to 1.00 for the editor and tree suites, 0.89
for every terminal run on both pins (see "The terminal baseline" below). Every
per-run value, allocation column and CPU share is in
[gpui-c016f436-us005-interleaved-2026-11-25.json](gpui-c016f436-us005-interleaved-2026-11-25.json).

**No metric of the new pin is more than 10 % slower than the old pin.** The
largest gaps are `lexer_viewport_query_60_rows` +3.5 %, `search_50k` +3.1 %,
`search_300k` +3.0 %, `resolve_runs_3750` +2.8 % and
`tree_sitter_keystroke_mid_file` +2.3 %, all of them code GPUI does not run
(the lexer, the tree search, the run resolver and tree-sitter), so the gaps
are placement of the same code in two binaries, as on the previous bump. The
layout and text paths that #67222 and #67223 changed read within 1 % of the old
pin (`layout_*`, `shape_cold_60_rows` +0.6 %, `prepaint_60_rows_warm` -3.1 %,
`shape_warm_60_rows` -6.0 %): assumption A4 holds, layout persistence costs
nothing measurable in these suites.

## Keystroke latency and the unfocused frame cap (US-006)

Debug builds of `a3f53dbb` and `226032bf` from their own worktrees, the two
thresholds of the latency probe in `terminal/element/mod.rs` lowered to 0 in
those copies only, as in the 703b5ac3 procedure. Each run starts the build on
its own `PANEFLOW_HOME` with one workspace holding one terminal (the login
shell, zsh), `PANEFLOW_LATENCY_PROBE=1`, `PANEFLOW_IPC_SCRIPTING=1` and
`RUST_LOG=warn`, sends `cat >/dev/null` through `paneflow send ... --submit`,
then types 200 letters 130 ms apart with `agent-desktop press` (Mutter's
RemoteDesktop interface), Enter every 40. Before typing, the driver checks
from a screenshot that the test window shows a solid (focused) cursor and
aborts otherwise; after each key it checks that the window's log gained a
`key-handler→paint-cpu` line and takes the first one, and aborts otherwise. No
run aborted. It then starts `yes stream`, counts terminal paints for 10 s
focused, launches GNOME Calculator, which takes the focus (checked on the
screenshots: the calculator is in front with its caret, and the test window's
cursor is not solid), and counts 10 s more. Runs alternate between the pins,
five per pin. The other agent session on the machine had stopped its own
synthetic input for the whole set.

## Visual pass on Wayland and X11 (US-007)

Release builds of both pins (debug builds of the same commits for the settings
pages, which the measurement copies open at startup through an environment
variable, since a window launched by the driver does not receive the
settings shortcut reliably). Each scene was launched three times on its own
`PANEFLOW_HOME` with the same 1400 by 900 window state: old pin, new pin, old
pin again (A/A), and each window captured on the display Mutter placed it on
(the second display, centered, in every capture). "Wayland" is GPUI's native
Wayland backend; "X11" is GPUI's X11 backend under Xwayland in the same GNOME
session (`WAYLAND_DISPLAY` unset), since GNOME 51 has no Xorg session. The
pixel counts compare the 1387 by 887 window rectangle of the old and new
captures; "Blended" is the translucent window material
(`linux_chrome_material` and `linux_terminal_material` on), "Themed" the opaque
one.

| Scene | Surfaces | Wayland Blended | Wayland Themed | X11 Blended | X11 Themed |
|---|---|---|---|---|---|
| Welcome page, no workspace | sidebar, "Star Paneflow on GitHub" card, outlined actions | 0 | 0 | 0 | 0 |
| Two panes split, top one focused | focus hairline, outlined tab chips, pane headers | 0 | 0 | 0 | 0 |
| Settings, General | rounded cards, outlined selects and switches | 0 | 0 | 0 | 0 |
| Settings, Appearance | rounded cards, outlined theme tiles, the selected tile's border | 0 (second set) | 0 | 0 | not captured |
| Two panes, the second detached into its own window | detached pane window | 48 | 48 | 48 | 48 |

- **Settings, Appearance, Wayland Blended:** the first set differed by 83 361
  pixels (at most 21 levels per channel), all of them where the remote desktop
  shown by a Remmina window behind the translucent window changed between the
  captures (its compressed screen content and dock); the old pin against
  itself differed more. A second set, with a still background, reads 0.
- **The detached window, 48 pixels:** 12 in each of its four rounded corners,
  at most 11 levels per channel, lighter on the new pin, the same on every
  backend and material, and 0 between the old pin and itself. These are the
  anti-aliased pixels of the window's corner border outside its fill: zed
  `e2f00a41ac` (#66972) composites the border through `over()`, which leaves a
