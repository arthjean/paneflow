# Browser runtime third-party notices

Paneflow's Browser dock loads a separate `paneflow-browser-host` process that
links the Chromium Embedded Framework runtime distributed alongside it. This
notice covers every file the deb, rpm, AppImage and tar.gz artifacts install
under `lib/paneflow/browser/`. It does not cover the terminal application, whose
native notices stay in
[native/libghostty/THIRD_PARTY_NOTICES.md](../libghostty/THIRD_PARTY_NOTICES.md).

Windows uses the signed CEF Windows64 archive recorded in `manifest.toml`. The
archive is staged under the same runtime directory with its `Release/*.dll`
files intact. The Windows client is loaded through the pinned cef-rs sandbox
contract: `bootstrap.exe` calls the exported `RunWinMain` entry with
`sandbox_info`; Paneflow does not use `browser_subprocess_path` as a bootstrap
shortcut. Windows presentation remains control-only until the EP-002 native
surface qualification.

The authoritative, per-artifact inventory is the SBOM generated by
`python3 scripts/browser-package.py sbom`. It lists every distributed file with
its SHA-256, the pinned component versions and the codec inventory probed from
the shipped `libcef.so`. This document is the human-readable summary of that
inventory; the SBOM is the machine-readable one, and both ship in
`share/doc/paneflow/`.

## Pinned runtime

The pins live in [manifest.toml](manifest.toml) and every distributed file has
an individual SHA-256 there. Packaging copies the pinned bytes without stripping
or rewriting them, so the installed runtime stays byte-identical to the audited
archive and Paneflow's own start-up verification (`verify_runtime`) can refuse a
tampered runtime.

## Codecs actually distributed

The codec set is a property of the compiled runtime, not of this document. It is
probed from the shipped `libcef.so` by looking for the FFmpeg decoder symbols
that only the Chrome branding of Chromium's bundled FFmpeg emits, and the result
is written into the per-artifact SBOM under `codecs` and `restricted_codecs`.

The hardened candidate currently pinned in `manifest.toml` was probed before
its final stripping step. It contains the MP3, FLAC and Vorbis decoders and does
not contain the H.264, HEVC or AAC decoders. The per-artifact SBOM records this
inventory and sets `redistribution` to `review_required` whenever a restricted
codec appears.

## Open items before distribution

These are recorded here because they block a Browser release, not because they
are optional polish.

- The candidate carries Chromium's generated `CREDITS.html`; every package
  installs it in the runtime and verifies it through the `chromium_credits`
  check.
- The candidate records CFI, icall CFI, ThinLTO, PGO, official-build flags and
  source/patch/build-log provenance. It remains development-only with
  `native_qualification = "hardened_candidate_not_qualified"` until Q-LNX-01
  and the remaining native release gates are executed.
- The Windows candidate is development-only with
  `native_qualification = "control_only_windows11"`; the Windows 10 1809
  matrix, release signing, renderer and presentation gates remain open.
