| F-01 | BLOCKING, fixed and rerun | `crates/paneflow-host/src/runtime.rs`, panic branch of the serve loop | After an injected runtime panic the session called `retire_terminal`, which hands the ConPTY master to the closer thread; closing the pseudo console ends the attached child, so the "recovery owner" kept an identity whose process had already been stopped implicitly. The test `a_runtime_panic_keeps_the_child_owned_until_an_explicit_stop_confirms_its_exit` only passed when its liveness check ran before the closer thread; under full-workspace load it failed. FR-02, FR-06, and unhappy path 20 require the child to stay owned until an explicit stop confirms its exit. | The panic branch calls the new `retire_engine`, which drops the writer and the terminal engine but keeps the master until `record_exit` releases it after the explicit stop. The test waits for `retired()` and then asserts the child stays live for one second. Host suite green natively afterwards. |
| F-02 | NON_BLOCKING, fixed | `crates/paneflow-host/src/host.rs`, test `a_restart_whose_persist_fails_restores_the_prior_record_without_a_stranded_start` | The barrier replaced the sessions directory once; on Windows a delete-pending entry held by the persistence writer or the on-access scanner returned `ERROR_DIR_NOT_EMPTY` (145) under load. Test fixture race, not a product defect. | The barrier retries the replacement for up to 5 s. |
| F-03 | BLOCKING (NFR-01), fixed and rerun | `crates/paneflow-host/src/viewport_scan.rs` | Every 500 ms the scan formatted the screen and enumerated the process table for every live session. At 50 idle sessions the host spent 43 % of one CPU on the `paneflow-host-viewport` thread (12 % at 10, 1.5 % at 1) against the 1 % NFR-01 budget, on both the clean commit and the F-01 build. | A session is rescanned only when its output stamp advanced since its last scan; the first scan and every session that emits bytes are unchanged. Host CPU at 50 idle sessions fell to 0.16 % (host + worker) and 0.0 % (host-only); the desktop topology fell from 47.6 % to 2.8 % in total. New test `a_session_without_new_output_is_not_rescanned_until_bytes_arrive`. |
| F-04 | BLOCKING, fixed in review | `persistent-20260922T155203Z-f88eb887620d.json`, host-only quick, W05 batch 9 | One `flood` session reached confirmed root exit but reported `2 descendant process(es) remain unresolved`, stayed `unverified`, was never reclaimed, and the host correctly refused the final shutdown (`1 live session(s) remain`). The fixture spawns no children and no fixture survived, so the two identities were adopted through a parent-pid match during the batch. The operator's own process-table probes ran on the machine during that batch, which the runbook forbids for performance cells. | Root cause found in review: on this machine `csrss.exe` + `wininit.exe` and `csrss.exe` + `winlogon.exe` list the dead `smss.exe` instances 1484 and 1660 as their parent, and a standard user cannot read their start times. ## Residual limits

- Windows on ARM64 is not a shipping target of the current archive manifest and
  is not claimed.
- Thread and handle counts come from the harness's native counters; no ETW or
  WPR trace was collected, so NFR-02 wait-reason attribution rests on the
  per-thread CPU attribution in the artifacts and on the automated tests.
- `paneflow host status` does not print the loaded ConPTY module; the identity
  above was taken from the live process table and the cache directory the host
  extracts the bundled payload to. The runbook sentence that names `host.status`
  for this is inaccurate until the host reports it.
- The report and the artifacts name the clean commit with `dirty: true`; the
  final candidate SHA exists only once the qualification and review repairs are
  committed.
