== Root cause (C2 and C4)
The worker served surface.split by committing the new surface to the layout, then creating the host session, then binding
it (bind_session). The window, which fetches the layout view after the events of the previous split, could read the
layout in that gap, see a terminal surface with no session, start its own shell for it and send its own bind_session.
 - window bind first -> the worker's bind is refused -> surface.split fails "-32070: the layout op was refused: invalid" (C4)
 - worker bind first -> the worker types the prompt into its own session; the window shows its other, empty shell (C2)
That is why only the second pane of the fan-out (fan[beta]) was hit. Trace of the lost races: after the 30 "before" runs,
`paneflow host stop` listed 13 extra live zsh sessions (cwd $SCRATCH/flowfix/repo) that no pane showed; after the 60
"after" runs it listed exactly the 3 sessions of the 3 panes of the one remaining workspace.
