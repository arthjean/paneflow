## C13: every in-place checkout switch goes through one guard

Entry points that change a checkout's files, found by reading every caller of `git switch`:
- New branch form with Worktree off: `switch_checkout_for_tab` (was guarded, own workspace only).
- Changes dock branch picker: `switch_diff_branch` in diff_dock/branch.rs (was not guarded: the bug).
Entry points that never switch in place (no guard needed, pinned green):
- Tab menu > a branch (Bind branch) and the pane palette's Branch rows: `bind_tab_to_branch`, which binds an existing worktree or creates one (`prepare_branch_checkout`), never `git switch` in the shared checkout.
- Tab menu > Create branch here (detached worktree): `git switch -c <name>` from the current HEAD, which names the checkout's branch and moves no file.
- Snapshot restore: creates a fresh worktree.

Fix: `PaneFlowApp::in_place_switch_refusal(checkout)` in tab_worktree.rs is the one guard, with the one wording
"An agent is working in this checkout; create a worktree instead". It now counts a working agent of any workspace
whose tab uses that checkout (before, only the form's own workspace). The form keeps showing it inline (its Worktree
toggle is the alternative); the dock shows it as an error toast with a "Create worktree" action that checks the branch
out in a worktree and binds the active tab to it.

  red: left None, right Some("An agent is working in this checkout; create a worktree instead")

## C16: PANEFLOW_WINDOW_BACKDROP on macOS

Decision: not a code bug; the docs over-promise. The variable is a Windows-only legacy knob being retired:
- tasks/prd-unified-window-backdrop.md D7: "`window_backdrop` and `PANEFLOW_WINDOW_BACKDROP` are retired ... `PANEFLOW_WINDOW_BACKDROP` is removed. A debug-only `PANEFLOW_DEV_BLUR_SUPPORT` replaces it for testing"; US-012 (EP-005, TODO) removes the remaining Windows read.
- Code: the only read is `window_backdrop_preference` in src-app/src/app/constants.rs, `#[cfg(target_os = "windows")]`; macOS and Linux resolve the backdrop from `background_style` (or the legacy config keys) only.
- DESIGN.md already scopes it to Windows (Windows 11 row: "blur needs `PANEFLOW_WINDOW_BACKDROP=blurred` for one launch").
Making macOS and Linux honor it would add reads of a variable the accepted PRD removes, so the fix is in the site docs:
configuration/schema.md, `window_backdrop` row, replace "`PANEFLOW_WINDOW_BACKDROP` overrides it for one launch." with
"On Windows only, `PANEFLOW_WINDOW_BACKDROP` overrides it for one launch; macOS and Linux ignore that variable."
troubleshooting.md never names the variable; nothing to change there.
No live run for C16: no code changed, and the audit's 51-backdrop-env-opaque.jpg already shows the variable ignored on macOS.
