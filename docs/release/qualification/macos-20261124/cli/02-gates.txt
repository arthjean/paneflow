$ paneflow send --help
Inject text into a pane WITHOUT submitting it (human-in-loop).

Requires `PANEFLOW_IPC_SCRIPTING=1` on the running instance; the text is written verbatim with no trailing newline so the user/agent reviews and presses Enter themselves - unless `--submit` is passed explicitly.

Usage: paneflow send [OPTIONS] <TARGET> <TEXT>

Arguments:
  <TARGET>
          Target: surface id, name, `cmdline:<substr>`, or `cwd:<path>`

  <TEXT>
          Text to inject (no trailing carriage return is added by default)

Options:
      --broadcast
          Send to EVERY pane matching the target (a multi-match selector is an error without this flag). Prints a `{sent, failed}` report

      --submit
          Submit the text (append a carriage return). Explicit opt-in: this is the ONLY way the CLI ever submits on the user's behalf, and it still requires the instance-side scripting gate

      --paste
          Force bracketed-paste delivery: the text is wrapped in `ESC[200~`/`ESC[201~` and, with `--submit`, the carriage return is sent separately after a calibrated delay so a TUI agent does not swallow it (EP-001). `--submit` toward an agent pane enables this automatically; pass `--paste` to force it (e.g. toward a shell) or `--paste` alone to wrap a non-submitted inject

      --report-file <PATH>
          Ask the agent to write its complete result to this file and print `REPORT_DONE <path>` after the file is fully written. The path is resolved relative to the caller's current directory

      --force
          Write even when the target agent waits for a decision (permission, menu, question) or no longer runs in the foreground. The forced write is logged by the instance

      --scope <SCOPE>
          From inside a Paneflow pane, writes stay in that pane's workspace. `all` reaches every workspace and needs PANEFLOW_IPC_ORCHESTRATION=1 on the instance
          
          [default: workspace]
          [possible values: workspace, all]

  -h, --help
          Print help (see a summary with '-h')
[exit=0]
