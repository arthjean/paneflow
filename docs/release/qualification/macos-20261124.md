physical Apple Silicon Mac, that everything `docs/user/` describes works in
the real app, closes the open macOS stories in `tasks/`, and fixes what it
finds. Every verdict below names its evidence. A check that cannot be run on
this machine is marked `unavailable` with the reason, never `pass`.

## Open defects and stale documentation

### Product decisions for Arthur

- **F4, two worktree reuse rules.** `paneflow up` and the API
  (`crates/paneflow-git/src/worktree_plan.rs`) refuse a branch checked out in a
  worktree Paneflow did not create, or in the project checkout, with "already
  checked out at". The GUI (`plan_branch_checkout`,
  `crates/paneflow-git/src/worktree.rs`) reuses any checkout that holds the
  branch. `worktrees.md` promises the GUI behavior and names `paneflow up` as
  another entry to the same flow. Either align the two paths or narrow the
  sentence to the GUI (`worktrees/14b-reuse-via-up.txt`).
- **The host's own gate refusals** (`surface.send_text disabled; set
  PANEFLOW_IPC_SCRIPTING=1 to enable` and the `*.orchestration disabled`
  messages) still name the deprecated environment variables. They are pinned
  by `protocol/app-conformance-v1.json`, and `scripting.md` promises that "a
  refused request still answers with its former message", so changing them is
  a protocol decision. `context7.json` and
  `examples/review-pipeline.flow.toml` mention the variables too.
- **`Cmd+Shift+Q` (`close_workspace`)** is also the key equivalent of macOS's
  Log Out item in the Apple menu. Which one wins was not tested, to avoid
  logging out the session under test.
